# 作者主导的学术论文协作编辑器

`scientific-manuscript-editor` 是一套面向科研作者的学术论文写作与修改规范。它让人工智能承担编辑、推理整理和表达优化工作，同时把论文的科学立场、证据边界和最终决定权留给作者。

它不只是把句子改得更流畅，也不把论文修改变成一套繁重的审查流程。它关注的是：作者究竟想说明什么，现有证据能够支持到哪里，读者还缺少哪一步推理，以及怎样把这些内容写成准确、直接、自然的论文语言。

## 为什么需要它

通用人工智能在修改论文时，常见的问题并不是语法错误，而是越过作者做科学决定：

- 把作者已经限定好的判断改成更强的命题，再补上一串“尚不能证明”“仍需进一步验证”；
- 为了显得严谨，罗列与当前论证无关的替代机制、局限性和未来工作；
- 一看到参考文献，就复制其句式、段落骨架甚至论证路线，把别人的科学问题带入作者的论文；
- 把局部润色扩大成全文审查，或者用修改说明、检查表和过程术语淹没真正需要交付的论文文本；
- 在长对话和多轮修改中，让已经否定的机制、旧术语或过时版本重新进入正文。

本技能针对这些问题建立了一套协作边界：人工智能可以充分发挥编辑能力，但不能替作者决定论文相信什么。

## 核心原则

### 作者决定科学立场，编辑负责把它写清楚

语法、措辞、句子拆分、冗余删除和不改变科学含义的局部重组，可以直接完成。新的机制、因果关系、证据角色、结论强度或贡献定位，应先作为建议说明其依据和影响，得到作者接受后再写入论文。

作者主导并不意味着把每个普通措辞都交还给作者选择。真正需要作者决定的是科学问题，而不是编辑本应完成的语言工作。

### 修改范围与修改幅度分开处理

作者指定的范围决定“哪里可以改”，文本的实际问题决定“需要改多少”。原文准确有效时保留；局部问题局部修复；当授权范围内的结构、逻辑或表达整体失效时，可以充分重写。若作者只要求处理一个问题，就不顺带改动其他内容。

### 先校准论断，再决定是否需要保留意见

严谨不是在每个结论后追加警告，而是让命题本身的对象、范围、因果强度和确定程度与证据相匹配。

如果作者写的是“一种可能解释”，就不应把它改写成“是否构成必然证明”，再郑重提醒“尚不能单独证明”。只有当省略某个边界会让读者误解测量对象、适用范围、解释依据或证据强度时，这个边界才应进入正文。

### 学习文献的功能，不复制文献的外形

参考文献可以帮助学习信息密度、推理展开程度、段落功能、文献进入论证的位置和结论强度，但不能自动成为作者论文的事实来源、论证框架或写作模板。

技能会区分“可以阅读”与“可以写入论文”：提供一篇文献，意味着可以检查它；并不自动授权引用、类比、反驳或移植其机制。最终文本应围绕作者自己的材料和科学关系重新组织，而不是对参考文献进行换词仿写。

### 论文正文只保留读者需要的科学内容

来源核查、备选解释、修改理由和不确定性分析可以留在协作对话中。论文正文应聚焦研究对象、证据、必要推理和科学意义，不把编辑过程写进论文。

### 证据边界不可越过

技能不会编造数据、方法、文献、机制或创新性，也不会把相关性写成因果性。数值、单位、样品名称、公式、引文以及图表编号均应保持可追溯。未实际核查的文献支持应明确标记为“尚未核实”，而不是凭记忆补全。

## 防御性写作通常怎样出现

这里的“防御性写作”不是指所有谨慎、限定或否定句，而是指正文的主要功能被自我保护、预先辩护和想象中的争论占据。判断依据是段落的科学任务、证据关系和读者是否真的需要这段话，而不是某个词是否出现。

下面这些是本技能重点防止的典型失真场景。

### 1. 先把主张说重，再用一大段话撤回来

常见路径是：原文只说“X 可能解释 Y”，修改时先写成“X 导致 Y”或“X 证明 Y”，随后再补上“但这并不能单独证明 Y”“仍不能排除其他可能”等防守段落。

正确做法是保留原命题的真实强度，直接写“X 可能解释 Y”；如果确实存在会改变读者理解的边界，就把它放在命题本身或紧邻位置，用一个具体条件说明，而不是先制造一个作者并未提出的强断言再反驳它。

### 2. 一个主张后面堆出整段“设防墙”

段落先给出发现或解释，后面连续出现“并不意味着……”“不能说明……”“尚不能证明……”“不排除……”“还需要进一步研究……”。如果这些句子没有提供新的证据、适用条件、设计信息或真实限制，它们只是在替作者预先回答假想批评。

技能会把必要边界压缩到真正需要的位置，把重复的免责声明、审稿人式反驳和空泛的未来工作移出正文。真正影响结果解释、研究范围、可重复性或结论成立条件的限定仍然保留。

### 3. 作者提供了一篇文献，人工智能就自动把它写进正文

提供文献只意味着“可以阅读和核查”，不等于“必须引用”，更不等于“必须拿它来和本文对比”。典型失真是：作者只是让人工智能参考一篇关于机制 A 的论文，生成稿却自动写成“不同于 A，本文提出 B”，凭空制造研究对象、条件或机制之间的对立。

正确做法是先确认这篇文献在当前任务中的角色：事实支持、术语来源、推理参考、风格样本，还是作者明确要求的比较对象。只有比较关系真实、证据已核实且确实服务于当前论证时，才把它写入正文；否则文献停留在协作过程，不污染作者自己的论证。

### 4. 把“作者曾经说过 A，后来否定 A”写成“不是 A，而是 B”

多轮协作中，早期草稿、讨论过的假设和已经撤回的机制只是历史背景。人工智能如果把它们重新写进当前正文，就会制造一个作者并不想保留的对立句式：“不是 A，而是 B”。

如果当前真正要表达的只有 B，就直接写 B。只有当 A 与 B 的区分本身是当前研究的科学结果、且读者需要知道这个对比时，才保留“不是 A，而是 B”这样的结构。作者最新确认的科学立场优先于旧草稿和人工智能曾经提出的方案。

### 5. 把参考文献的写法、结构和论证路线搬过来

学习文献可以借鉴它如何安排信息密度、证据与解释的距离、文献进入段落的位置和结论的强度；不能复制它的句式骨架、段落顺序、连接词节奏、研究机制、局限性或“换词后的原文”。作者的材料必须围绕自己的科学关系重新组织。

### 6. 把正常的科学限定语当成“软弱”，一律删掉

`可能`、`或可解释为`、`与……一致`、`提示` 等表达有时正是在准确标记观察、解释和推论之间的距离。它们不因为看起来谨慎就自动构成防御性写作。技能同时防止两种失衡：证据不足时夸大，证据足够时又被连续自我否定压低。

### 7. 为了显得严谨，正文开始解释作者自己为什么这样做

“为了公平起见”“本文没有讨论……”“我们知道这个结果不理想”“本文仅提供一些启示”这类句子，很多时候是在管理姿态，而不是传递科学信息。应优先写清楚研究条件、实际结果、适用范围和证据作用；只有当某项选择或限制会影响读者评价研究时，才保留具体说明。

### 8. 一个短句请求被扩大成全文审查

作者只让人工智能修改一个句子，人工智能却开始重建机制、检查所有引文、罗列替代解释或大幅重写整段。这种“为了防止出错而先把所有问题都说一遍”的做法，本身也会制造防御性和过度编辑。

技能会让处理深度服从当前任务：局部问题局部解决；只有请求本身涉及推理、证据组织或全文一致性时，才扩大检查范围。

### 9. 用空泛的谨慎压低已经成立的贡献

当证据已经支持一个清楚、有限的结论时，反复改成“初步探索”“仅提供一些参考”“可能具有一定意义”，并不会自动增加严谨性，反而会让读者看不见研究真正建立了什么。技能追求的是“证据支持范围内最直接的表达”，而不是普遍把结论改弱。

这些场景只是识别线索，不是固定禁词表。`可能`、`然而`、`不是……而是……` 或“进一步研究”在承担真实科学功能时都可以保留；最终判断必须回到段落任务、证据关系和作者当前决定。

## 能做什么

| 任务 | 处理重点 |
| --- | --- |
| 局部润色与翻译 | 保持科学命题和证据关系，只处理授权范围内的语言、术语或图表引用 |
| 段落与章节重写 | 重建论点、证据、必要推理和段落推进关系 |
| 科学逻辑审查 | 指出证据与结论之间的断点、强度失配或隐含科学选择 |
| 引言 | 从真实研究问题出发组织背景、缺口和研究目标 |
| 方法 | 按科学依赖关系呈现可复现过程，不虚构缺失参数 |
| 结果 | 围绕证据关系组织发现，而不是机械跟随实验顺序或图号 |
| 讨论 | 将结果转化为有边界的科学理解，避免结果复述和防御性写作 |
| 标题、摘要与结论 | 压缩已建立的科学论证，不拔高因果性、确定性或适用范围 |
| 文献辅助写作 | 核查事实和引文，或学习可迁移的推理与表达特征，避免内容和结构污染 |
| 全文一致性 | 维护术语、数值、论断强度、图表引用和作者最新科学立场 |

## 三种工作深度

技能会根据任务本身选择足够但不过度的处理深度：

1. **局部修改**：适用于翻译、术语修正、图表引用和不改变科学关系的语言优化。
2. **实质性修改**：适用于重建推理、修复科学逻辑、组织证据或重写段落与章节。
3. **全文综合**：适用于投稿前检查、跨章节一致性，以及标题、摘要、结论与正文的协调。

短文本不一定只需局部修改，长对话也不自动触发全文审查。判断依据是完成当前请求究竟需要处理到哪一层。

## 安装

### Codex

在 PowerShell 中运行：

```powershell
git clone https://github.com/deathcats4/scientific-manuscript-editor.git "$env:USERPROFILE\.codex\skills\scientific-manuscript-editor"
```

在 macOS 或 Linux 终端中运行：

```bash
git clone https://github.com/deathcats4/scientific-manuscript-editor.git ~/.codex/skills/scientific-manuscript-editor
```

安装后重新启动 Codex，或重新加载技能列表。

### 其他支持技能规范的智能体

将整个仓库放入该工具规定的技能目录，并确保 `SKILL.md` 位于技能根目录。具体目录位置以所用工具的说明为准。

## 使用方式

安装后，可以直接描述论文任务；也可以显式调用：

```text
使用 $scientific-manuscript-editor 修改这一段讨论。保留我当前的科学判断，重点检查证据到解释之间是否缺少必要推理。
```

更具体的调用方式通常会得到更符合预期的协作结果：

```text
这段是我已经确认的版本，只做语言润色，不改变论断强度。
```

```text
先审查这一段的科学逻辑，不要直接改写。若涉及新的机制选择，先告诉我它会怎样改变结论。
```

```text
阅读这篇参考文献，学习它如何组织证据和推进段落，但不要复制句式、结构，也不要把它的机制带入我的论文。
```

```text
检查这一节是否存在防御性写作。保留真正影响结论边界的限定，删除为了显得谨慎而重复添加的辩护。
```

```text
按段落和我协作：每次只处理一段，先说明问题和修改依据，等我确认后再继续。
```

## 协作边界

| 情况 | 技能的处理方式 |
| --- | --- |
| 不改变科学含义的编辑决定 | 直接完成 |
| 可能改变机制、因果、范围或结论的选择 | 提出建议并说明后果，由作者决定 |
| 作者明确要求整合文献 | 在授权范围内选择有效关系并写入 |
| 仅提供文献供阅读或学习风格 | 不自动引用，不移植其事实、机制和结构 |
| 信息不足但不影响其他部分 | 标出受影响位置，继续完成可安全处理的内容 |
| 缺失信息会导致正文失真 | 明确指出缺口，不用看似合理的内容补全 |

## 一句话定位

这是一个作者主导的学术论文协作编辑器：作者决定研究要表达什么，人工智能帮助把观察、证据、推理和必要边界组织成清楚、直接、可核查的论文语言。
