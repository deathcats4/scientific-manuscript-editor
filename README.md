# 作者主导的学术论文协作编辑器

`scientific-manuscript-editor` 面向中英文科研论文的起草、修改、翻译和审查。它把语言、推理整理和段落组织放在同一个工作流中，同时保留作者对科学立场、证据边界和最终表述的控制。

它关注四件事：

- 作者想让读者理解什么；
- 现有数据和文献能够支持到哪里；
- 读者需要哪一步必要推理；
- 怎样把这些内容写成准确、直接、自然的论文语言。

## 为什么需要它

通用人工智能在修改论文时，常见的问题并不是语法错误，而是越过作者做科学决定：

- 把作者已经限定好的判断改成更强的命题，再补上一串“尚不能证明”“仍需进一步验证”；
- 为了显得严谨，罗列与当前论证无关的替代机制、局限性和未来工作；
- 一看到参考文献，就复制其句式、段落骨架甚至论证路线，把别人的科学问题带入作者的论文；
- 把局部润色扩大成全文审查，或者用修改说明、检查表和过程术语淹没真正需要交付的论文文本；
- 在长对话和多轮修改中，让已经否定的机制、旧术语或过时版本重新进入正文。

本技能针对这些问题建立了一套协作边界：人工智能可以充分发挥编辑能力，但不能替作者决定论文相信什么。

## 核心原则

### 作者决定科学内容，编辑完成语言工作

语法、措辞、句子拆分、冗余处理、局部重排和保持原意的修辞调整可以直接完成。新机制、因果关系、证据角色、结论强度或贡献定位属于科学选择：先说明依据和后果，再由作者决定是否写入论文。

作者控制科学判断，同时把普通编辑工作交给技能完成。这样既能保持作者的研究立场，也能避免把每个措辞选择都变成确认环节。

### 证据决定表述强度

命题的对象、范围、因果程度和确定性与证据保持一致。必要的限定、真实的条件和可复现信息进入正文；与读者理解无关的姿态管理、空泛辩护和想象中的替代机制留在协作层。

技能保留数字、单位、公式、样品名、标识符、引文以及图表编号的可追溯性。只使用作者提供或实际核查过的事实；支持尚未核实的引文会明确标出。

### 论证连续不等于逐段宣布目的

引言需要有清楚的科学推进，但推进应由相邻论点之间真实的承接关系产生。技能会在内部检查研究问题、缺口和研究动作，却不会为了完成这些检查而让每段重复“因此”“基于此”或“本研究旨在”。只有当显式的研究动作句补充了读者无法从前文恢复的具体关系时，才保留它。

### 简短请求先恢复论证，而不是先提问

“帮我写引言”这样的简短请求不会自动变成一轮反问。技能会先从已有材料——稿件其他章节、摘要、图表、旧稿和已确认的讨论决定——恢复研究对象、已有认识、具体障碍和本文能补充的内容；材料足够时直接组织成稿，存在实质性分歧时给出推荐方案及理由，只有恢复后仍然缺失且会改变核心论证的信息才提问。段落数量、篇幅分配和衔接方式属于编辑工作，不交给作者决定。

同一恢复流程适用于各章节：方法从供给的记录（底稿、报告、图表和已确认的决定）恢复实际流程，结果从图表与数据恢复已确立的发现，讨论从已接受的解释和文献角色恢复论证基础。直接成稿时可以在协作层附上简短的恢复依据与组织思路供作者核对；作者提供的详细提纲按同一标准执行——落实其科学关系而非逐条照抄，主张照常校准，有出入时明确指出而不是默默服从或默默丢弃。

作者授权检索文献时，按论证需要覆盖奠基性工作、近期进展和直接相关研究（包括该方向的代表性工作）；有争议的机制同时检索反向、阴性或限定性证据，检索不到时明确说明未找到而不是暗示不存在；每个来源先核对可比性（对象、尺度、区域、方法条件）与记录状态（更正、撤稿、预印本与正式版本），再逐条核实其结论确实支持所引句子后插入。代表性作者的工作用于查漏补全，不构成独立的引用理由。未获检索授权时，主张保持在已核实支持的范围内，明确指出缺少支持的具体位置，而不是为迁就现有引文削弱命题。

### 大块起草可拆成“规划—写作—审查”

拆分是条件触发，不是大任务一律默认：只在规划上下文已有残留（长对话、被否定的草稿、检索输出）、任务真正大块（多章节、投稿级修改、全新整章起草）或作者点名要简报/子代理/核对点时才拆；干净的对话里单上下文一遍起草、随附简短恢复思路通常就够，而拆分要花两到三遍的生成量。拆分时，规划上下文负责恢复论证、做科学决定并编写交接简报——论证计划按命题链书写（简报的文体就是成稿的文体），锁定事实逐字携带，只附必要材料，写明边界与回传方式；写作在只拿简报的干净上下文里进行，正文不接触规划过程的残留。简报默认直接派发、随成稿一并可见——它同时就是那条用户本来很难自己写出的清晰指令；只有作者点名要核对、仍存在会被写作端默默代答的科学选择、或规划者判断简报尚不可安全执行时，才暂停等作者确认。返回的草稿先审查再交付：审查端拿到与写作端同一套证据，缺证据按阻塞项回传而不是当作“无问题”；规划上下文有残留时由第三个干净上下文审查，否则由规划者直接执行综合检查；审查后任何人再改过内容，都要对改动及其依赖重跑相应范围的最终检查。句子和单段修改从不拆分；翻译按范围处理——单句、单段和局部翻译不拆，多章节或全文翻译可以不拆写作上下文，但交付前必须完成连续性检查（术语与模态统一、标题—摘要—结论一致、交叉引用有效），作者要求逐段确认时按逐段协作执行。角色与简报格式见 [handoff-drafting.md](references/handoff-drafting.md)。

### 当前稿件是默认的风格来源

需要接入现有论文的段落，优先沿用相邻的已确认正文、术语和语体。作者指定参考文献用于学习时，参考文献可以提供信息密度、推理展开、段落功能、文献嵌入方式和论断校准；它的事实、机制、独特句式和段落骨架仍然属于原文。

旧稿默认承担术语、研究对象和上下文连续性。作者明确要求学习旧稿表达方式时，才把它加入风格参考。没有现稿或指定样本时，使用符合章节和学科的中性学术语体。

### 自然学术写作来自论证本身

自然度意味着清楚、地道、克制，并且符合学科和读者。技能重点修复空泛开头、重复总结、虚假对立、机械段落节奏、防御性回撤和编辑过程残留；同时保留真正承担科学功能的限定语、被动语态、并列结构、术语重复和逻辑连接。

它诊断可观察的表达特征，不把某个词、标点、句式或检测器评分当作作者身份证据。`may indicate` 可以准确表达推断强度；有充分依据的 `establishes` 也可以保留。只有在表达承担空泛引导时，才会删去 `It is important to note that` 一类套话。

详细规则：

- [academic-naturalness.md](references/academic-naturalness.md)：自然度与 AI 风格模式检查；
- [academic-protection.md](references/academic-protection.md)：数字、术语、证据、限定和学术表达功能的保护。

## 防御性写作通常怎样出现

这里的“防御性写作”不是指所有谨慎、限定或否定句，而是指正文的主要功能被自我保护、预先辩护和想象中的争论占据。判断依据是段落的科学任务、证据关系和读者是否真的需要这段话，而不是某个词是否出现。

下面这些是本技能重点防止的典型失真场景。

### 1. 先把主张说重，再用一大段话撤回来

常见路径是：原文只说“X 可能解释 Y”，修改时先写成“X 导致 Y”或“X 证明 Y”，随后再补上“但这并不能单独证明 Y”“仍不能排除其他可能”等防守段落。

正确做法是保留原命题的真实强度，直接写“X 可能解释 Y”；如果确实存在会改变读者理解的边界，就把它放在命题本身或紧邻位置，用一个具体条件说明，而不是先制造一个作者并未提出的强断言再反驳它。

### 2. 一个主张后面堆出整段“设防墙”

段落先给出发现或解释，后面连续出现“并不意味着……”“不能说明……”“尚不能证明……”“不排除……”“还需要进一步研究……”。如果这些句子没有提供新的证据、适用条件、设计信息或真实限制，它们只是在替作者预先回答假想批评。

技能会把必要边界压缩到真正需要的位置，把重复的免责声明、审稿人式反驳和空泛的未来工作移出正文。真正影响结果解释、研究范围、可重复性或结论成立条件的限定仍然保留。

### 3. 作者提供了一篇文献，人工智能就自动把它写进正文

提供文献只意味着“可以阅读和核查”，不等于“必须引用”，更不等于“必须拿它来和本文对比”。典型失真是：作者只是让人工智能参考一篇关于机制 A 的论文，生成稿却自动写成“不同于 A，本文提出 B”，凭空制造研究对象、条件或机制之间的对立。

正确做法是先确认这篇文献在当前任务中的角色：事实支持、术语来源、推理参考、风格样本，还是作者明确要求的比较对象。只有比较关系真实、证据已核实且确实服务于当前论证时，才把它写入正文；否则文献停留在协作过程，不污染作者自己的论证。

### 4. 把“作者曾经说过 A，后来否定 A”写成“不是 A，而是 B”

多轮协作中，早期草稿、讨论过的假设和已经撤回的机制只是历史背景。人工智能如果把它们重新写进当前正文，就会制造一个作者并不想保留的对立句式：“不是 A，而是 B”。

如果当前真正要表达的只有 B，就直接写 B。只有当 A 与 B 的区分本身是当前研究的科学结果、且读者需要知道这个对比时，才保留“不是 A，而是 B”这样的结构。作者最新确认的科学立场优先于旧草稿和人工智能曾经提出的方案。

### 5. 把参考文献的写法、结构和论证路线搬过来

学习文献可以借鉴它如何安排信息密度、证据与解释的距离、文献进入段落的位置和结论的强度；不能复制它的句式骨架、段落顺序、连接词节奏、研究机制、局限性或“换词后的原文”。作者的材料必须围绕自己的科学关系重新组织。

### 6. 把正常的科学限定语当成“软弱”，一律删掉

`可能`、`或可解释为`、`与……一致`、`提示` 等表达有时正是在准确标记观察、解释和推论之间的距离。它们不因为看起来谨慎就自动构成防御性写作。技能同时防止两种失衡：证据不足时夸大，证据足够时又被连续自我否定压低。

### 7. 为了显得严谨，正文开始解释作者自己为什么这样做

“为了公平起见”“本文没有讨论……”“我们知道这个结果不理想”“本文仅提供一些启示”这类句子，很多时候是在管理姿态，而不是传递科学信息。应优先写清楚研究条件、实际结果、适用范围和证据作用；只有当某项选择或限制会影响读者评价研究时，才保留具体说明。

### 8. 一个短句请求被扩大成全文审查

作者只让人工智能修改一个句子，人工智能却开始重建机制、检查所有引文、罗列替代解释或大幅重写整段。这种“为了防止出错而先把所有问题都说一遍”的做法，本身也会制造防御性和过度编辑。

技能会让处理深度服从当前任务：局部问题局部解决；只有请求本身涉及推理、证据组织或全文一致性时，才扩大检查范围。

### 9. 用空泛的谨慎压低已经成立的贡献

当证据已经支持一个清楚、有限的结论时，反复改成“初步探索”“仅提供一些参考”“可能具有一定意义”，并不会自动增加严谨性，反而会让读者看不见研究真正建立了什么。技能追求的是“证据支持范围内最直接的表达”，而不是普遍把结论改弱。

这些场景只是识别线索，不是固定禁词表。`可能`、`然而`、`不是……而是……` 或“进一步研究”在承担真实科学功能时都可以保留；最终判断必须回到段落任务、证据关系和作者当前决定。

## 工作深度

技能依据当前请求选择合适的处理深度：

| 深度 | 适用任务 | 处理重点 |
| --- | --- | --- |
| 局部编辑 | 翻译、术语修正、图表引用、句子或短段润色 | 在授权范围内优化语言并保持原有科学关系 |
| 实质性修改 | 重建推理、修复逻辑、组织证据、重写段落或章节 | 明确论点、证据、必要推理、边界和段落推进 |
| 全文综合 | 投稿阶段检查、跨章节一致性、标题—摘要—结论协调 | 统一术语、数值、论断强度、图表引用和贡献表达 |

短文本如果需要重建推理，仍然可以进行实质性修改；普通局部编辑则保持在请求范围内。完整路由见 [SKILL.md](SKILL.md)。

## 文献的使用方式

一篇文献在当前任务中可以承担一种或多种明确角色：

| 角色 | 可迁移内容 |
| --- | --- |
| 事实或引文支持 | 已核实的背景、数据关系和引用位置 |
| 术语与概念 | 定义、缩写、方法或学科惯例 |
| 推理参考 | 证据如何展开为解释，如何校准结论强度 |
| 风格样本 | 信息密度、段落节奏、文献嵌入和论证粒度 |
| 比较对象 | 作者明确要求讨论的研究、机制或解释框架 |

先确定文献角色，再决定读取范围和写入方式。最终文字回到作者自己的研究问题、数据、图表、术语和结论，形成属于作者的论证。

相关规则见 [reference-learning.md](references/reference-learning.md) 和 [style-source-contract.md](references/style-source-contract.md)。

## 科学推理与章节写作

实质性任务会在内部建立一个简洁工作模型：

1. 读者需要理解或接受什么；
2. 哪些观察、结果、分析或来源支持它；
3. 哪一步非显然推理需要写出来；
4. 哪个条件或不确定性会改变结论含义；
5. 哪些内容已经是作者决定，哪些仍是候选方案。

按章节加载相应参考：

- [introduction.md](references/introduction.md)：研究背景、缺口、问题和目标；
- [methods.md](references/methods.md)：可复现的方法依赖关系与参数完整性；
- [results.md](references/results.md)：围绕证据关系组织发现；图注/表注作为可独立阅读的展示说明书来写；
- [discussion.md](references/discussion.md)：解释、比较、机制和结论边界；
- [manuscript-reasoning.md](references/manuscript-reasoning.md)：跨章节的段落推理和结构；
- [scientific-integrity.md](references/scientific-integrity.md)：主张强度、因果边界和引文支持；
- [synthesis.md](references/synthesis.md)：标题、摘要、结论和贡献压缩；
- [continuity-and-consistency.md](references/continuity-and-consistency.md)：长文档、跨章节和多轮决策中的当前作者状态。

## 交付形式

- 起草或改写：返回可直接放入论文的文字；
- 逻辑审查：给出发现及其科学后果，是否改写取决于用户请求；
- 引文或证据审查：区分已核实支持、缺少支持和支持尚未核实；
- 翻译：返回自然的目标语言，并保持科学含义与模态；
- 逐段协作：只交付作者当前选择的单元，确认后再继续下一单元；
- “只给修改稿”：只返回修改后的文本，除非存在一个必须回答的阻塞问题。

每次交付前按任务范围检查修改单元的科学关系、术语、数字、引文、语体和自然度。缺少的上下文会明确标注检查边界。

## 使用示例

安装后可以直接描述论文任务，也可以显式调用：

```text
使用 $scientific-manuscript-editor 修改这一段讨论。保留我当前的科学判断，重点检查证据到解释之间是否缺少必要推理。
```

```text
这段是我已经确认的版本，只做语言润色，保持论断强度、数字和引用不变。
```

```text
先审查这一段的科学逻辑，再告诉我哪些地方需要作者决定；暂时不输出改写稿。
```

```text
阅读这篇参考文献，学习它如何组织证据和推进段落。把可迁移的推理和表达特征用于我的材料。
```

```text
按段落和我协作：每次处理一段，先说明问题和修改依据，等我确认后再继续。
```

### 其他支持技能规范的智能体
