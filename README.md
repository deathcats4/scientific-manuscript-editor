# 作者主导的学术论文协作编辑器

`scientific-manuscript-editor` 面向中英文科研论文的起草、修改、翻译和审查。它把语言、推理整理和段落组织放在同一个工作流中，同时保留作者对科学立场、证据边界和最终表述的控制。

它关注四件事：

- 作者想让读者理解什么；
- 现有数据和文献能够支持到哪里；
- 读者需要哪一步必要推理；
- 怎样把这些内容写成准确、直接、自然的论文语言。

## 核心原则

### 作者决定科学内容，编辑完成语言工作

语法、措辞、句子拆分、冗余处理、局部重排和保持原意的修辞调整可以直接完成。新机制、因果关系、证据角色、结论强度或贡献定位属于科学选择：先说明依据和后果，再由作者决定是否写入论文。

作者控制科学判断，同时把普通编辑工作交给技能完成。这样既能保持作者的研究立场，也能避免把每个措辞选择都变成确认环节。

### 证据决定表述强度

命题的对象、范围、因果程度和确定性与证据保持一致。必要的限定、真实的条件和可复现信息进入正文；与读者理解无关的姿态管理、空泛辩护和想象中的替代机制留在协作层。

技能保留数字、单位、公式、样品名、标识符、引文以及图表编号的可追溯性。只使用作者提供或实际核查过的事实；支持尚未核实的引文会明确标出。

### 当前稿件是默认的风格来源

需要接入现有论文的段落，优先沿用相邻的已确认正文、术语和语体。作者指定参考文献用于学习时，参考文献可以提供信息密度、推理展开、段落功能、文献嵌入方式和论断校准；它的事实、机制、独特句式和段落骨架仍然属于原文。

旧稿默认承担术语、研究对象和上下文连续性。作者明确要求学习旧稿表达方式时，才把它加入风格参考。没有现稿或指定样本时，使用符合章节和学科的中性学术语体。

### 自然学术写作来自论证本身

自然度意味着清楚、地道、克制，并且符合学科和读者。技能重点修复空泛开头、重复总结、虚假对立、机械段落节奏、防御性回撤和编辑过程残留；同时保留真正承担科学功能的限定语、被动语态、并列结构、术语重复和逻辑连接。

它诊断可观察的表达特征，不把某个词、标点、句式或检测器评分当作作者身份证据。`may indicate` 可以准确表达推断强度；有充分依据的 `establishes` 也可以保留。只有在表达承担空泛引导时，才会删去 `It is important to note that` 一类套话。

详细规则：

- [academic-naturalness.md](references/academic-naturalness.md)：自然度与 AI 风格模式检查；
- [academic-protection.md](references/academic-protection.md)：数字、术语、证据、限定和学术表达功能的保护。

## 工作深度

技能依据当前请求选择合适的处理深度：

| 深度 | 适用任务 | 处理重点 |
| --- | --- | --- |
| 局部编辑 | 翻译、术语修正、图表引用、句子或短段润色 | 在授权范围内优化语言并保持原有科学关系 |
| 实质性修改 | 重建推理、修复逻辑、组织证据、重写段落或章节 | 明确论点、证据、必要推理、边界和段落推进 |
| 全文综合 | 投稿阶段检查、跨章节一致性、标题—摘要—结论协调 | 统一术语、数值、论断强度、图表引用和贡献表达 |

短文本如果需要重建推理，仍然可以进行实质性修改；普通局部编辑则保持在请求范围内。完整路由见 [SKILL.md](SKILL.md)。

## 文献的使用方式

一篇文献在当前任务中可以承担一种或多种明确角色：

| 角色 | 可迁移内容 |
| --- | --- |
| 事实或引文支持 | 已核实的背景、数据关系和引用位置 |
| 术语与概念 | 定义、缩写、方法或学科惯例 |
| 推理参考 | 证据如何展开为解释，如何校准结论强度 |
| 风格样本 | 信息密度、段落节奏、文献嵌入和论证粒度 |
| 比较对象 | 作者明确要求讨论的研究、机制或解释框架 |

先确定文献角色，再决定读取范围和写入方式。最终文字回到作者自己的研究问题、数据、图表、术语和结论，形成属于作者的论证。

相关规则见 [reference-learning.md](references/reference-learning.md) 和 [style-source-contract.md](references/style-source-contract.md)。

## 科学推理与章节写作

实质性任务会在内部建立一个简洁工作模型：

1. 读者需要理解或接受什么；
2. 哪些观察、结果、分析或来源支持它；
3. 哪一步非显然推理需要写出来；
4. 哪个条件或不确定性会改变结论含义；
5. 哪些内容已经是作者决定，哪些仍是候选方案。

按章节加载相应参考：

- [introduction.md](references/introduction.md)：研究背景、缺口、问题和目标；
- [methods.md](references/methods.md)：可复现的方法依赖关系与参数完整性；
- [results.md](references/results.md)：围绕证据关系组织发现；
- [discussion.md](references/discussion.md)：解释、比较、机制和结论边界；
- [manuscript-reasoning.md](references/manuscript-reasoning.md)：跨章节的段落推理和结构；
- [scientific-integrity.md](references/scientific-integrity.md)：主张强度、因果边界和引文支持；
- [synthesis.md](references/synthesis.md)：标题、摘要、结论和贡献压缩；
- [continuity-and-consistency.md](references/continuity-and-consistency.md)：长文档、跨章节和历史版本中的当前作者状态。

## 交付形式

- 起草或改写：返回可直接放入论文的文字；
- 逻辑审查：给出发现及其科学后果，是否改写取决于用户请求；
- 引文或证据审查：区分已核实支持、缺少支持和支持尚未核实；
- 翻译：返回自然的目标语言，并保持科学含义与模态；
- 逐段协作：只交付作者当前选择的单元，确认后再继续下一单元；
- “只给修改稿”：只返回修改后的文本，除非存在一个必须回答的阻塞问题。

每次交付前按任务范围检查修改单元的科学关系、术语、数字、引文、语体和自然度。缺少的上下文会明确标注检查边界。

## 使用示例

安装后可以直接描述论文任务，也可以显式调用：

```text
使用 $scientific-manuscript-editor 修改这一段讨论。保留我当前的科学判断，重点检查证据到解释之间是否缺少必要推理。
```

```text
这段是我已经确认的版本，只做语言润色，保持论断强度、数字和引用不变。
```

```text
先审查这一段的科学逻辑，再告诉我哪些地方需要作者决定；暂时不输出改写稿。
```

```text
阅读这篇参考文献，学习它如何组织证据和推进段落。把可迁移的推理和表达特征用于我的材料。
```

```text
按段落和我协作：每次处理一段，先说明问题和修改依据，等我确认后再继续。
```

```powershell

git clone https://github.com/deathcats4/scientific-manuscript-editor.git ~/.codex/skills/scientific-manuscript-editor
```
